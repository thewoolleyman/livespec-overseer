# overseer-malformed-state-recovery — charter and findings

Opened 2026-10-30 at the maintainer's direction, by the gitops-fleet-capacity-monitoring
coordinator (livespec-dev-tooling-dfixhe), after a tracked session defeated its own restart.

## The incident

From 2026-10-26 15:37Z the coordinator session for gitops-fleet-capacity-monitoring wrote
`working: …` into `tmp/overseer/gitops-fleet-capacity-monitoring/.overseer-state`. That
value is not in the state-file token table (`SPECIFICATION/contracts.md` §"The state file").
The daemon logged `MALFORMED state file … treated as no declaration`, but it then stopped
injecting the low-context wrap-up. The session ran four days without a restart, compacted
repeatedly, fell to 4% context, and the daemon logged 68 `danger-non-responder … A human
must act` alerts that reached no human. Evidence: `tmp/overseer/daemon.log` (2026-10-29
23:14Z to 2026-10-30 01:34Z), and the 2026-10-30 18:28Z handoff on livespec-dev-tooling-dfixhe.

## Finding 1 — a conformance defect (no spec change)

`overseer/_supervisor_threshold.py:75` gates the wrap-up paste on `not obs.malformed`. The
ratified spec does not:

- `contracts.md` §"The state file": a value outside the table is "treated as NO
  declaration (fail-closed)". The one carve-out it names is the keep-going NUDGE, not the
  wrap-up.
- `contracts.md` §"The wrap-up injection": the paste is excluded only for a gated pane, a
  pane waiting on a human, or one carrying `blocked:`, `ready`, `done` or a fresh
  `winding-down`; "a malformed state value remains fail-closed as no declaration".

A session with no state file receives the wrap-up. A malformed file must therefore receive
it too. The code's extra gate makes an invented token an opt-out from restart.

## Finding 2 — the bad file persists (spec addition, minimal)

Even with finding 1 fixed, a malformed file keeps standing, and a session told (by a
compaction-borne rule) to rewrite it each tick keeps doing so. Minimal design, no new paste
type and no new command:

- On the tick the daemon observes a malformed value, it renames the file to
  `.overseer-state.rejected` in the same track directory, replacing any earlier copy. The
  evidence is preserved and the track returns to plain "no declaration".
- The next wrap-up injection delivered to that track carries one line naming the rejected
  value and the four session tokens.
- The operator surfacing is unchanged.

This changes the state-file contract, so it is ratified first through propose-change and
delegated revise (`spec_governance.revise_decision_mode: "delegated"`).

## Deferred

  discussed before anything is filed, to avoid over-design. Reconsidered with the
  maintainer; it is not a child of this plan until then.
- Routing "a human must act" alerts to a push channel. Not requested; noted for the
  overseer owner.
