## How to inspect and drive

Every command here is copy-pasteable as written.

Inspect read-only — last 40 lines of the worker pane:

```sh
tmux capture-pane -p -t supervise-plan-residual-gaps -S -40
```

`-S -40` starts 40 lines back. Do NOT pipe to `tail -N` — `-N` is a placeholder
and `tail` rejects it.

Short instruction — send the text, VERIFY, then send Enter SEPARATELY:

```sh
tmux send-keys -t supervise-plan-residual-gaps -- '<one line>'
tmux capture-pane -p -t supervise-plan-residual-gaps -S -10   # confirm it landed
tmux send-keys -t supervise-plan-residual-gaps Enter          # only after verifying
```

Do NOT use the one-shot `… -- '<line>' Enter` form. Measured against a live
worker pane: the trailing `Enter` argument lands the text in the prompt but does
NOT submit it — the instruction sits queued until `Enter` is sent as a separate
call. This applies to SHORT instructions, not just pasted blocks.

Longer text — load from a file, paste, VERIFY, then Enter separately:

```sh
tmux load-buffer -b sup /tmp/msg.txt
tmux paste-buffer -b sup -t supervise-plan-residual-gaps
tmux capture-pane -p -t supervise-plan-residual-gaps -S -20   # confirm it landed
tmux send-keys -t supervise-plan-residual-gaps Enter          # only after verifying
```

A landed paste renders as `[Pasted text #N +M lines]`. Anything else means it
did not land.

**Re-check for an open picker immediately before EVERY paste.** A picker
swallows pasted text and reads it as KEYSTROKES, so an unlucky paste can
navigate or answer a maintainer-owned question. Never answer a picker via its
"Type something" option from a driving session — that cancels the whole batch
and discards answers already recorded on it; send the decision as a plain
message instead.

Idle plus queued input means STUCK, not idle. Never name a variable `TMUX`, and
never run `kill-server` on the maintainer's socket.

**Never kill the acting overseer daemon.** It runs in tmux
`livespec-overseer:1.1`, supervises every tracked session in the fleet, and is
the shipped product rather than part of any one thread. Every other rule here
protects the one track you govern; this one's blast radius is the whole fleet,
which is why the generic kill-server warning does not cover it.

**Distinguish idle-done from wedged by `stop_reason`, not by silence.** In the
worker's transcript under
`~/.claude/projects/-data-projects-livespec-overseer/<id>.jsonl`, a last
assistant message with `stop_reason: end_turn` means finished and waiting; a
tool result with no following assistant turn means wedged. They look identical
in the pane. Recovery from a wedge is TWO Escapes — the first only repaints the
UI, and a message resent after it silently re-queues.

## Decision-vetting rubric

Escalate only decisions that are genuinely BLOCKING — meaning no legitimate
action can proceed under any assumption you could state and correct later.
Outward-facing, sensitive-path, second-opinion and authorization-category are
NOT reasons to escalate. State the assumption and keep going.

The boundary that does stop you: never REMOVE, WEAKEN, or SKIP an existing
check. That is a property of the change, not of any file path.

Drive decision prep first, then surface the finished result with the question.

Genuinely blocking for this thread: whether the residue lands as `overseer-7lv`
slices or as `overseer-byvxlp` children; the groom's cut and acceptance; and
any change to the FLOOR items (`overseer-hbr.16`, `overseer-hbr.4`).

## No idle, no silent block

A conflicting lane owned by another track is NOT a thread-wide blocked state. If
some action is owned elsewhere: (1) stand down on that action ONLY; (2)
enumerate the remaining non-conflicting work; (3) drive the next concrete safe
action immediately; (4) only if NO legitimate non-conflicting action exists, ask
exactly one maintainer-facing blocking question with the recommended answer
first. Never convert "someone else owns X" into idling or a `blocked:`
declaration.

## Never end a turn without an armed re-entry

Dispatching work, writing a status report, and ending the turn reads like
diligence and is indistinguishable from abandonment.

- The worker is an EXTERNAL tmux session, not a harness-tracked background task.
  Its completion emits NO notification.
- A status report is not a work product that can end a turn. Narration is not
  movement.
- "I'll keep driving" / "I'll check back" is an INTENTION, not a mechanism.
- The daemon will not cover for you: an open `AskUserQuestion` suppresses its
  wrap-up injection into that pane, so the condition that most needs attention
  is the one that mutes the only other watcher.

**[R1] Arm on ANY open obligation — not only while the worker is mid-flight.**
The shipped contract scopes this to a mid-flight worker. That is the hole this
thread exists to close, and it cost 8h05m in the session that found it: the
worker was correctly PARKED and the SUPERVISOR held the open gate, so no trigger
fired. Before ending any turn, ask **"is there an open obligation, held by
anyone, whose resolution should bring me back?"** If yes, arm something. A
worker that is idle-and-gated is precisely when you are the only moving part.

**[R1] The wake condition need not be a pane.** A pane-diff watcher cannot see a
PR merge, a file appearing, or a peer replying. Match the watcher to the event:

```sh
# Pane watcher — worker mid-flight. Detect busy by pane CHANGE, not status text.
prev=""; stable=0
for i in $(seq 1 180); do            # ~60 min ceiling
  sleep 20
  pane=$(tmux capture-pane -p -t supervise-plan-residual-gaps -S -40)
  case "$pane" in
    *"Enter to select"*) echo "WAKE: picker open"; exit 0 ;;
  esac
  if [ "$pane" = "$prev" ]; then stable=$((stable+1)); else stable=0; prev="$pane"; fi
  if [ "$stable" -ge 3 ]; then echo "WAKE: pane unchanged ~60s — idle"; exit 0; fi
done
echo "WAKE: watcher ceiling reached — worker still busy, RE-ARM NOW"
```

```sh
# Forge watcher — a PR you are waiting on. Exits on any terminal state.
until [ "$(gh pr view <NUM> --repo <OWNER/REPO> --json state -q .state)" != "OPEN" ]; do
  sleep 60
done
echo "WAKE: PR <NUM> reached $(gh pr view <NUM> --repo <OWNER/REPO> --json state -q .state)"
```

**[R5] Expiry is itself a wake, never an intention.** The pane watcher's ceiling
message is a WAKE that obliges an immediate re-arm — treat "re-arm" appearing in
your notifications as an action item, not a status line. If you cannot re-arm,
say so in the obligation record below rather than letting the loop lapse

## [R3] Handing an obligation to a peer track

"Another track owns it" is not a handoff. A handoff is complete only when:

1. You have told that track's SUPERVISOR — not its worker; never cross-drive
   another track's worker.
2. They have CONFIRMED it is not already in progress or imminent, so you do not
   race them.
3. They have CONFIRMED they removed it from their own plan and marker, so it
   does not live in two places — or explicitly declined, which you take back to
   the maintainer rather than argue peer-to-peer.
4. It is recorded in your obligation record until they confirm, and struck only
   on their confirmation.

Until all four hold, the obligation is still YOURS. Precedent for what the gap
costs: `livespec-console-beads-fabro-6ma`, a correctly diagnosed P1 that sat six
days in a tenant whose owners could not fix it.

## AskUserQuestion presentation rules

Every maintainer-facing action is an AskUserQuestion call carrying a
recommendation — never a prose question, which sits unnoticed in a pane. Put the
recommended option first and label it Recommended, and make every option state
its own cost. Batch ripe valves into a single call rather than trickling them,
per this repo's recorded convention. Use full repository names. Put `---` as the
final line before a picker.

## Standing safety clauses

Repeat these in every instruction sent to the supervised session: never pass
`--no-verify`; halt and report on hook failure; never touch another session's
worktrees or branches; never kill the acting overseer daemon; verify against the
forge after a fetch, never a possibly stale working tree. Every tracked-file
change goes worktree → PR → rebase-merge; never commit on the primary checkout,
and use `mise exec -- git …` so hooks fire.

**[R4] Verification discipline.**

- **A filed item is a claim with a timestamp.** Re-read any work-item, bug, or
  status before reporting it as current. Five P1 titles were once relayed as
  present-tense blockers when two were already dead, and the framing reached a
  merged handoff on master.
- **An exit code through a pipe is the last command's.** `… | tail -35; echo
  "EXIT=$?"` reports `tail`, not your CLI. Establish outcomes from ARTIFACTS —
  merged PR, ledger row, cut snapshot — never from exit codes, and never from a
  piped one even when you think you are being careful.
