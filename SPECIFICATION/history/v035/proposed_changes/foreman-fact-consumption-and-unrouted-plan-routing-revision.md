## Decision and Rationale

Accepted with modifications required by four rounds of independent ratification review. Round 1 blocked four times, three of them one root cause: the clauses were written in the vocabulary of ungoverned presentation prose rather than the ratified tree, naming a per-plan counter, a bound, a classifier, a tick input and a seat/foreman split that the tree does not define — and one clause was circular, because the tree ratifies seat as the session itself. The fourth was the capacity clause absence branch shipping without a scenario. Round 2 blocked three times, each on a repair: the spec fix landed but its pinning scenario still required the removed pipeline and reinstated the circularity; both escalation scenarios still keyed to the removed classifier; and the clause asserted that starvation is already bound in this tree, which is false — that word appears in no ratified specification file. Round 3 blocked once, again on a repair: replacing whitelisted with a DELEGATION FLOOR pointer in one clause left whitelisted remedy stranded in the adjacent paragraph and both scenarios, with no antecedent anywhere, making the refusal arming predicate and its boundary undecidable against the tree. Round 4 returned NO BLOCKERS. The filed proposal text is left unchanged as the record of what was proposed; the modifications below are what is ratified.

## Modifications

One: the consecutive-unactioned count and the UNROUTED-PLAN BOUND are stated as tree obligations rather than borrowed from prose — the foreman records, per tracked plan, the number of consecutive ticks in which it took no action, reset to zero by any tick that actions the plan; the bound is named maintainer-owned configuration rather than given a number, and an unconfigured bound resolves UNDETERMINED. Two: NOT-DETERMINED is replaced by UNDETERMINED, the term this same section already ratifies for an unavailable picker state, with matching surface-and-fail-closed semantics. Introducing a second uppercase term for one concept would have been permanent after ratification, and is the exact vocabulary collision this amendment condemns elsewhere. Three: every obligation binds the foreman directly. The classifier, the proposal-carrying tick input and the seat/foreman split are gone, removing three unratified nouns and one circularity, and losing nothing the matrix asked for — it asked that the remedy be determined and the escalation refused, not that any named component do it. Four: the remedy and the escalation refusal both name the DELEGATION FLOOR enumeration of unsticking acts, which is ratified and closed, in place of an undefined whitelist. Both clauses and all their scenarios use that one name. Five: the starvation prohibition no longer claims a tree binding. It states that the term is already in use for the unrelated shell and wind-down liveness conditions and that reusing it would make the vocabulary ambiguous — true, and checkable, where the original was neither. Six: three scenarios beyond those filed. The capacity absence branch, which is the closest analogue of the motivating incident in which three surfaces each inferred an occupied slot rather than reading a verdict. The reset obligation, without which an implementation treating the count as cumulative passes every other scenario and then fires the condition on actively worked plans. And the first scenario rewritten to pin the repaired clause rather than the removed pipeline. Seven: the wait-state clause cites the plan-tree write prohibition by section name rather than by direction, since that prohibition sits below the insertion point. Eight: the heading-coverage entries are NOT carried in resulting_files, which cannot reach a file outside the spec target; they land as an ordinary edit in the same commit.
